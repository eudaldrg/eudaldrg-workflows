# Lean startup context

Three user-level settings that keep the first request of a Claude Code session small, why they
exist, what each one costs you, and how to undo them. The `setup-lean-context` skill applies them;
`html-design` and `html-diagramming` replace what the first one takes away.

```json
{
  "permissions": { "deny": ["Artifact"] },
  "env": { "ENABLE_TOOL_SEARCH": "true" },
  "promptSuggestionEnabled": false
}
```

## Why the startup context matters

Every request in a session re-sends the whole prompt prefix: system prompt, tool schemas,
`CLAUDE.md`/`AGENTS.md`, memory, then the conversation so far. Prompt caching makes re-sending
cheap, not free — each step pays **prefix size × cache-read price**, and every cache miss (the
cache expired, the prefix changed) pays **prefix size × cache-write price**. Whatever is in the
first request is therefore paid for on every single step of the session, and it also takes
context-window room the actual work could have used.

Measured on 2026-10-03 (found and measured with [tokentee](https://github.com/eudaldrg/tokentee),
reading the request transcripts), the first request of an interactive session on Opus 5.5 was
**~121k tokens** before any work had happened. Two things dominated.

## The settings

### `env.ENABLE_TOOL_SEARCH = "true"` — defer MCP tool schemas

With the default (`auto`), the full JSON schema of every MCP tool was sent up front: the claude.ai
connectors (Gmail, Drive, Calendar, Docs), the Chrome browser tools, and any other plugin's MCP
servers. With `true`, only their **names** are sent; when Claude needs one it fetches that
schema through the built-in `ToolSearch` tool and can then call it.

- **Measured:** first request ~121k → ~39k tokens (in a project with a `CLAUDE.md`, memory and
  hooks).
- **Costs you:** one extra round-trip the first time a session uses a given MCP tool, and the
  model now has to know a tool exists by name rather than by its description. In practice the
  names are descriptive enough; the schema arrives the moment it is needed.
- **Re-enable:** remove the key (back to `auto`) or set it to `false` to always load everything.

### `permissions.deny: ["Artifact"]` — drop the largest built-in tool

Built-in tools are always sent with full schemas; no setting defers them. The largest by far is
**Artifact** (publishes HTML pages to claude.ai): 34.4k characters of schema — a 19.9k-character
description plus 33 parameters, about **11.3k tokens**. That is roughly as much as the other 12
fully loaded built-in tools combined (30.8k characters). Its description also instructs the model
to publish finished work without being asked, which made publishing eager: reports went to a
hosted page when they were meant to stay local.

Denying a tool removes it from the request entirely. Denying `Artifact` also removes its
companions `ArtifactComments` and `ArtifactData`.

- **Measured:** A/B in fresh interactive sessions in an empty directory, prompt `say ok`:
  **35,274** tokens plain, **23,940** with the deny — **−11,334**.
- **Measure interactively.** `claude -p` never includes the Artifact tool, so a headless run shows
  no difference.
- **Not removed:** the built-in skills `artifact-design` and `artifact-diagramming` still load in
  full with the deny active (tested). Their guidance is still good; the `html-design` and
  `html-diagramming` skills in this plugin reuse it for local HTML files.
- **Costs you:** no publishing to claude.ai. Pages are written as local `.html` files instead and
  viewed with your own tooling. A deny in user settings wins over any project-level allow, so
  re-enabling it for one project means reverting it globally.

### `promptSuggestionEnabled: false` — no suggestion request per turn

Prompt suggestions (the greyed-out next prompt offered after a reply) are generated by a separate
request on the main model that reads the full context, once per turn. Off, that request is gone.

- **Costs you:** the suggestion itself. Nothing else depends on it.
- **Re-enable:** remove the key, or toggle it in `/config`.

## What it is worth

At the Opus 5.5 rates this plugin's status line uses ($4/MTok input, cache reads at ×0.05 =
$0.20/MTok, one-hour cache writes at ×2 = $8/MTok):

| Removed from every request | per step (cache read) | per cache miss (1h write) | 100-step session, reads only |
|---|---|---|---|
| Artifact, ~11.3k tokens | ~$0.002 | ~$0.09 | ~$0.23 |
| deferred MCP schemas, ~82k tokens | ~$0.016 | ~$0.66 | ~$1.64 |

Small per step, but it is paid on every step of every session, and the context-window room comes
back too. Prices change; the ratio is the point.

## When to re-enable Artifact

The deny is a workaround for the tool's size, not a judgement on artifacts. Lift it when Claude
Code either defers `Artifact` behind ToolSearch like MCP tools, or trims its schema to the size of
the other built-in tools. (Both were suggested to Anthropic via `/feedback` on 2026-10-03.)

**Check:** temporarily remove the deny (`wf_lean_context_setup.py revert`, or delete the entry by
hand), start a plain **interactive** session, send one message, and open that session's transcript
(`~/.claude/projects/<project>/<session-id>.jsonl`). Its `prompt_snapshot` attachment lists the
tools that were sent in full under `tools`. If `Artifact` is no longer there — or is there at a
size comparable to the other built-ins — drop the deny for good. Otherwise re-apply.

## Applying and reverting

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/wf_lean_context_setup.py" status          # what is set, what apply would change
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/wf_lean_context_setup.py" apply [--dry-run]
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/wf_lean_context_setup.py" revert [--dry-run]
```

The script touches only these three keys in `~/.claude/settings.json`. A plugin manifest cannot
contribute `permissions`, and a hook must never change the user's settings behind their back, so
this is always an explicit skill invocation. Changes take effect in the next session.
